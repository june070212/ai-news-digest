How it works

About

A static digest of GitHub and Microsoft developer news, rebuilt on a schedule by GitHub Actions.

Why the digest is prerendered

GitHub Pages serves static files, and the upstream RSS feeds don't send CORS headers — so the browser can't fetch them directly. Instead scripts/build-digest.mjs runs in CI, collects every feed, ranks the results, and writes assets/data.json. The page just renders that file, so it loads instantly and works offline once cached.

Sources

  • GitHub Changelog — github.blog/changelog/feed/
  • The GitHub Blog — github.blog/feed/
  • Microsoft Developer Blogs — devblogs.microsoft.com/feed/
  • .NET Blog — devblogs.microsoft.com/dotnet/feed/
  • Microsoft Developer changelog — developer.microsoft.com/api/changelog/rss
  • Azure Blog — azure.microsoft.com/en-us/blog/feed/

Ranking

Scoring is deterministic — no model in the loop. Each story earns points for its source weight, AI and shipping vocabulary, breaking-change signals, an explicit bonus for Copilot news, and recency. The resulting score maps to a high, medium, or low importance badge.

De-duplication

The Microsoft Developer changelog republishes GitHub stories, so entries are keyed on the normalized title plus the final URL path segment and the highest-scoring copy wins. Org attribution comes from the destination hostname rather than the feed it arrived on, so a republished GitHub post is still labelled GitHub.

Rebuild schedule

The deploy workflow runs on every push to main, twice a day on a cron, and on demand via Run workflow. If every feed fails the build stops rather than publishing an empty digest, so the last good digest stays live.

Run it locally

git clone https://github.com/nguyenda_microsoft/ai-news-digest.git
cd ai-news-digest
node scripts/build-digest.mjs
python3 -m http.server 8000

Then open http://localhost:8000/.
